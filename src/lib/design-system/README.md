# MUSANAD Design System

Generated by the **Design System Agent** (lovable-extracted mode) during Phase 0' from `design-tokens.json` (Pass 7 Lovable extraction). **Locked.**

## Overview

The design system is **token-driven** and **CSS-first** — built on Tailwind 4's `@theme inline` directive. There is no `tailwind.config.js`. All tokens live in `src/styles.css` and are surfaced to TypeScript through `tokens.ts`.

Source-of-truth: `src/styles.css`
Type-safe API: `src/lib/design-system/tokens.ts`
Runtime control: `src/lib/design-system/theme-provider.tsx`

## Palette — 7 names

The MUSANAD palette uses a 7-name model expressed in OKLCH for perceptual uniformity. Each status color has paired `-tint` (background) and `-ink` (high-contrast text) variants.

| Name | Role | OKLCH (light) |
|---|---|---|
| `ink` | Primary brand neutral — headings, body, primary buttons | `oklch(0.22 0.04 255)` |
| `gold` | Brand accent / CTA / focus ring | `oklch(0.72 0.12 78)` |
| `sage` | Success / signed / completed | `oklch(0.66 0.08 155)` |
| `amber` | Warning / pending / expiring | `oklch(0.78 0.13 75)` |
| `terracotta` | Error / rejected / destructive | `oklch(0.62 0.14 35)` |
| `slate` | Regulatory / neutral info / secondary buttons | `oklch(0.55 0.04 240)` |
| `plum` | Resubmission / amended | `oklch(0.52 0.11 320)` |

## Semantic mapping

The 12 mandatory shadcn-style semantic tokens map to the palette above:

| Semantic token | Maps to |
|---|---|
| `--primary` | `--ink` |
| `--primary-foreground` | off-white |
| `--secondary` | `--surface` |
| `--secondary-foreground` | `--ink` |
| `--accent` | `--gold-tint` |
| `--accent-foreground` | `--ink` |
| `--muted` | `--surface` |
| `--muted-foreground` | `--ink-muted` |
| `--destructive` | `--terracotta` |
| `--destructive-foreground` | off-white |
| `--background` | warm paper white |
| `--foreground` | `--ink` |

Use Tailwind utility classes that consume these tokens (`bg-primary`, `text-foreground`, `border-border`, etc.) — never raw hex.

## Typography — 4 families

| Token | Family | Usage |
|---|---|---|
| `--font-sans` | Inter | Body text (LTR) |
| `--font-arabic` | IBM Plex Sans Arabic | Body text (RTL / `lang="ar"`) |
| `--font-arabic-display` / `--font-ceremonial` | Aref Ruqaa | Ceremonial — signing pages, certificates |
| `--font-mono` | JetBrains Mono | Numerals, IDs (always LTR even inside RTL) |

Fonts are loaded via Google Fonts CDN. The base layer in `styles.css` switches to `--font-arabic` automatically when `<html lang="ar">` or `<html dir="rtl">` is set.

## Border radius — 6 levels

`sm` 6px · `DEFAULT` 8px · `md` 10px · `lg` 14px · `xl` 20px · `2xl` 28px

## Animations

`fadeIn`, `slideUp`, `scalePress`, `blink` — all respect `prefers-reduced-motion`.

## Dark mode

Toggle by adding `class="dark"` on `<html>`. `ThemeProvider` does this automatically based on the `theme` preference (`light` | `dark` | `system`). All OKLCH tokens have dark inversions in the `.dark { }` block of `styles.css`.

## RTL handling

The provider mirrors the Lovable runtime model: locale changes write `dir` and `lang` attributes to `<html>`. The base CSS layer swaps the body font to IBM Plex Sans Arabic for Arabic. Monospace text remains LTR (numbers, IDs) via `unicode-bidi: isolate`.

## Usage

```tsx
// Wrap the app once at the root.
import { ThemeProvider } from '@/lib/design-system/theme-provider';

export default function Root({ children }) {
  return (
    <ThemeProvider defaultTheme="system" defaultLocale="en">
      {children}
    </ThemeProvider>
  );
}
```

```tsx
// Read or change theme / locale anywhere.
import { useTheme } from '@/lib/design-system/theme-provider';

function ThemeToggle() {
  const { resolvedTheme, toggleTheme } = useTheme();
  return <button onClick={toggleTheme}>{resolvedTheme === 'dark' ? 'Light' : 'Dark'}</button>;
}

function LangToggle() {
  const { locale, setLocale } = useTheme();
  return <button onClick={() => setLocale(locale === 'en' ? 'ar' : 'en')}>{locale === 'en' ? 'العربية' : 'English'}</button>;
}
```

```tsx
// Type-safe token access (rare — prefer Tailwind utilities).
import { tokens } from '@/lib/design-system/tokens';

const chartColors = tokens.charts.light;
```

## Constraints

- **No raw hex codes** in feature components — use Tailwind semantic utilities.
- The design system is **locked** — modifications require a project-wide audit (see `00-design-system-agent.md`).
- The 49 shadcn primitives + 12 patterns components from the Lovable repo are **ported and hardened** in feature modules by the Component Transformer; they are **not** redefined here.

## Runtime dependencies

`theme-provider.tsx` imports from `react`. These resolve once M0's FE Implementation step adds `package.json` and runs `npm install`. `tokens.ts` is dependency-free.
